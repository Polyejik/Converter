# Portfolio Pulse v36 — оценка готовности

28 сентября 2026. Решение: **рабочее локальное демо, не готово к подписке для команды**. Проверка ролей выполнена на синтетическом проекте; интервью с настоящими клиентами и пилот на их данных не проводились.

| Область | Подтверждено | Граница |
| --- | --- | --- |
| Портфель и график | Создание проекта, базовый план/прогноз, зависимости, риск и CEO сводка; восстановление старых перекрытий | Данные хранятся локально у одного пользователя; нет согласования изменения базового плана и полной истории решений |
| Люди и табель | Назначения, доступность, перенос одиночного назначения, отправка и принятие часов, стоимость по ставке; доменные и UI тесты | Общая база табелей и ролей отсутствует; профиль в демо не является безопасной аутентификацией |
| Счета и деньги | Счёт, прогноз оплаты, частичное поступление, остаток, предупреждение о задержанном этапе | Нет синхронизации с бухгалтерской системой, банковской сверки и полного аудита ручных изменений |
| Письма и голос | Worker/D1 код и тесты для импорта, классификации и транскрипции; UI сохраняет исходный текст при ошибке | Worker не подключён к реальному домену, Access, D1 и почтовому ящику; ключ OpenAI не предоставлен, качество на живых примерах не измерено |
| Качество выпуска | `npm test` и `npm run check:worker` прошли; UI сценарий покрывает роль координатора, контрактника и дивизионного руководителя | Не было теста двух независимых пользователей, физического микрофона, реального почтового потока, резервного восстановления или целевых устройств |

## Что мешает продавать как SaaS

1. **Общая защищённая база** для проектов, кадров, ставок, часов, платежей и аудита. Нужны серверные роли, миграция localStorage с предпросмотром и проверка конфликта правок двух пользователей.
2. **Рабочая интеграция**: Cloudflare D1 и Access, секрет OpenAI, домен API и выделенный почтовый адрес. После настройки нужен испытательный поток без конфиденциальных данных, затем пилот с согласованной политикой хранения.
3. **Доказательство ценности**: реальные координаторы, финансовая команда и CEO должны выполнить свои задачи; измерить время обновления, ошибки прогноза, найденные ранние отклонения и решения. Замечания из нашей ролевой симуляции — полезный вход, но не пользовательские интервью.
4. **Операционное доверие**: резервная копия с проверенным восстановлением, версии бизнес-записей, журнал ответственных, мониторинг ошибок и полноты входящих, контроль стоимости AI.

## Приёмка следующего этапа

Два человека с разными правами одновременно меняют один проект через API; конфликт сохраняет обе версии для разрешения. Бухгалтер видит выставленный счёт и частичное поступление из той же базы, CEO видит автора и время каждого изменения. Специалист отправляет часы, руководитель принимает их с другого устройства. Сбой сети не теряет черновик, восстановление из резервной копии проверено. Только после этого имеет смысл называть продукт готовым к платной подписке.
