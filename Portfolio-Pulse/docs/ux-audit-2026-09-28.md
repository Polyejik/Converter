# UX-аудит по ролям · 28 сентября 2026

Проверены опубликованные экраны CEO, руководителя дивизиона, координатора, контрактного специалиста, главного бухгалтера и специалиста. Проверка проводилась на демонстрационном срезе 31 июля 2026 года. В финансовых формах изменения не сохранялись.

## Критичные наблюдения

1. Проект с ручным критическим риском и нулевым отклонением не объяснял причину риска в карточке CEO.
2. Демо-генератор показывал этапы августа и сентября завершёнными на срез 31 июля.
3. Радар счетов предлагал действия по уже полностью оплаченным вехам.
4. Форма поступления заранее подставляла весь остаток долга.
5. Личная неделя специалиста открывалась на текущую календарную неделю, хотя данные портфеля относились к историческому срезу.
6. Системные следующие действия части проектов были на английском в русском интерфейсе.

В v34 исправлены правила завершения этапа относительно даты среза, исключение оплаченных вех из радара, пустая начальная сумма поступления с проверкой остатка, объяснение ручного риска, отображение системных действий на русском и начальная неделя специалиста. Для существующих локальных демо-записей будущие «завершённые» этапы приводятся к состоянию среза. Финансовые исторические правки пользователя не сбрасываются.

## Полезные сценарии

- CEO: брифинг → проблемные проекты → карточка.
- Координатор: очередь решений → быстрое обновление с прогнозом и сигналом для CEO.
- Специалист: работа по дням и предварительный разбор голосового примера перед добавлением в черновик.

## Дальнейшие решения

- Отдельный режим живых данных должен показывать дату последней синхронизации каждого источника и отличаться от исторического демо-среза.
- Следующее действие руководителя должно иметь владельца, срок, состояние выполнения и подтверждение, а не только текст в карточке.
- Финансовые операции требуют серверного журнала, прав доступа, закрытия периода и проверки дубликатов; локальное демо этого не заменяет.
