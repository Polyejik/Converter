# Portfolio Pulse: годовой сценарий использования (v38)

Дата прогона: 29 сентября 2026. Это воспроизводимая симуляция в тестовом браузере и доменной модели, а не отзывы реальных пользователей или год эксплуатации в production.

## Сценарий

- 12 новых проектов с датами старта с августа 2026 по июль 2027, пять повторяющихся клиентов и два полностью одинаковых новых контракта через форму.
- 52 последовательные недели, 2 080 часов технической работы, отправка и согласование каждой недели, назначение специалиста в 12 проектов.
- Перенос назначения между этапами, сдвиг срока из-за данных клиента, сохранение нового прогноза платежа (регрессионный UI сценарий v35).
- Выставленный счёт, частичное поступление, расторжение контракта, архивирование завершённого оплаченного проекта и новый счёт в другом дивизионе.
- Проверка ролей специалиста, координатора без проектов, руководителя дивизиона и CEO; сброс демо после годовой записи.

## Найдено и исправлено

| Проблема | Последствие | Исправление и проверка |
| --- | --- | --- |
| Координатор без собственных проектов видел первые пять чужих | Неверная область доступа | Пустая область остаётся пустой; UI проверка |
| Архивирование убирало полученные деньги из исторического факта и неоплаченные счета из взыскания | Искажённые показатели CEO и пропущенная дебиторка | История поступлений и активный прогноз разделены; архивные выставленные неоплаченные счета видны в платежах; проверка до и после архива |
| Архив не фиксировал, контракт потерян, завершён или приостановлен | Причина ухода исчезала | Обязательные исход и причина, события закрытия и восстановления; проверка сохранения |
| Два одинаковых контракта, созданных формой, могли получить один ID/код | Риск перезаписи и путаницы | Уникальный ID и следующий код при создании; тест двух одинаковых вводов |
| Сброс портфеля оставлял 52 недели часов и HR данные | Ложные данные после сброса | Единый сброс с подтверждением; проверка пустого табеля |
| Архивная дебиторка чужого дивизиона попадала в область менеджера | Нарушение разграничения | История и взыскание ограничены текущим дивизионом; тест FOREIGN-001 |
| Новый табель на потерянный контракт можно было отправить после архива | Часы начислялись закрытому контракту | Новые черновики блокируются при отправке; одобренная история остаётся; регрессионный тест |

## Проверки

`node qa-v38/test-year.cjs`, `npm test`, `npm run test:api`, синтаксическая проверка трёх обновлённых JavaScript файлов. Сценарий выполняется на тестовой копии с контролируемым состоянием браузера и не изменяет данные пользователя.

## Ограничения и следующий архитектурный шаг

Продукт всё ещё является локальным демо на GitHub Pages: портфель и табели хранятся в localStorage данного браузера, роли переключаются в демо, а дата управленческого среза зафиксирована на 31 июля 2026. Годовой прогон проверяет запись данных и переходы состояний, но не доказывает корректность динамических KPI на каждом месячном срезе. Для реального годового использования нужны серверная модель данных с авторизацией, миграциями и аудитом, настраиваемая дата среза и финансовый период, резервирование и многопользовательская синхронизация. API Worker для AI покрыт отдельными тестами, но не заменяет это хранилище.
